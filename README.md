## 1.Course Information

This course covers Object-Oriented Programming (OOP), using Java as the primary teaching language. It begins with the most fundamental concepts and gradually builds comprehensive object-oriented programming skills.

The course employs a three-pronged learning approach combining “theoretical instruction, practical guidance, and hands-on assignments.” The theoretical component uses a series of lecture slides to cover core object-oriented concepts, including classes and objects, inheritance, polymorphism, encapsulation, abstraction the Java Collections Framework, file handling, and GUI programming. The practical component utilizes GitHub repositories for version control. During weekly tutorial sessions, students create corresponding directories within the repository and complete assigned Java coding tasks. The ultimate goal of the course is to enable students to apply object-oriented principles to independently write Java programs that solve real-world problems, covering the entire development process from command-line tools to graphical user interface applications.

## 2.Course Description

This is a systematic introductory course on Java object-oriented programming, designed to help us understand the core concepts of object-oriented programming and master how they are implemented in the Java language. The course begins with “What Is Java?” and introduces Java’s history, language features, and the cross-platform advantage of “Write Once, Run Anywhere,” helping us build a comprehensive understanding of the language. The course then delves into the four pillars of object-oriented programming—encapsulation, inheritance, polymorphism, and abstraction—explaining the definition, principles, implementation methods, and practical application scenarios of each concept in turn.

In the section on encapsulation, the course emphasizes the importance of grouping data and methods within classes and achieving data hiding through access modifiers (private, public, protected). Using examples such as student information, it illustrates how to control access to internal state through getter and setter methods, thereby ensuring data integrity and security. In the inheritance section, the course explains the relationship between superclasses and subclasses, introduces types such as single inheritance and multi-level inheritance, and demonstrates how to achieve code reuse through the `extends` keyword and `super` calls. In the polymorphism section, the course uses examples of method overriding (`@Override`) and superclass references pointing to subclass objects to illustrate how the same method call can exhibit different behaviors depending on the actual object type. In the section on abstraction, the course covers the definition and use of abstract classes and abstract methods, demonstrating how to unify interface specifications through abstract design.

## 4.Tutorial Summary

**Week 1：Setting Up a Development Environment and Getting Started**

This module focuses on setting up the development environment and providing an introduction to Java programming. Students need to log in to their GitHub accounts and create an OOP repository, become familiar with using the GitHub Codespaces online IDE, and master basic Git commands (init, status, add, commit, push). In the `tutorial_1` directory, create two files—`HelloWorld.java` and `StudentGrade.java`—to write, compile, and run their first Java program, thereby establishing a complete understanding of the process from source code to executable program.


**Week 2：Classes and Objects: The Basics**

This tutorial delves into the core concepts of object-oriented programming. Create Main.java and Student.java in the tutorial_2 directory. Students need to define the `Student` class, which includes attribute fields such as name and student ID; write a constructor to initialize the object; and implement member methods. In the `Main` class, instantiate a `Student` object and call its methods to understand the fundamental relationship that “a class is a template and an object is an instance,” and to master the use of the `this` keyword and the process of method invocation.

**Week 3-4：Inheritance and Polymorphism**

This tutorial creates four files—Main.java, Person.java, Student.java, and Lecturer.java—in the week3_4 directory to demonstrate the combined use of inheritance and polymorphism. Person serves as the parent class and contains two private fields—name and id—as well as a constructor and the introduce() method. Both Student and Lecturer inherit from Person using the extends keyword and override the introduce() method with the @Override annotation to output “I am a student.” and “I am a lecturer.”, respectively. In the `Main` class, a parent class reference is used to point to a subclass object (`Person p = new Student()`). When the `introduce()` method is called, it dynamically binds to the corresponding implementation based on the actual object type, demonstrating runtime polymorphism. The expected output, in order, is “I am a person,” “I am a student,” and “I am a lecturer.”

**Week 5：Encapsulation and Data Hiding**

The tutorial creates `main.java`, `Student.java`, and `documentation.txt` in the `week_5` directory to build a student information management system. The `Student` class declares fields such as student ID, name, and CGPA as `private` and provides access only through getter and setter methods, ensuring that the internal state cannot be directly modified from the outside. Students are required to answer three reflective questions in `documentation.txt`: Why are variables declared as `private`? What risks would arise if they were declared as `public`? Why should getter and setter methods be used? Through this week’s tutorial, students will gain a deep understanding of the significance of encapsulation as a cornerstone of object-oriented design.

**Week 6：Advanced Inheritance and Access Control**

The tutorial creates `employee.java`, `lecturer.java`, and `main.java` in the `week_6` directory to further explore the concept of inheritance. With `Employee` as the parent class, `Lecturer` inherits from it using the `extends` keyword. The `protected` modifier allows the subclass to access the parent class’s protected members, and the `super` keyword is used to call the parent class’s constructor and member methods. This week’s focus is on mastering the hierarchy of access modifiers (private → protected → public) and the role of `super` in the inheritance chain, as well as understanding the balance between code reuse and access control.

**Week 7：Abstract Classes and Abstract Methods**

In the tutorial, create Appliances.java and Main.java in the week_7 directory to introduce abstract concepts. Define the abstract parent class `Appliance`, which includes the `brand` property, the `displayBrand()` method, concrete methods such as `turnOn()` and `turnOff()`, and an abstract method `operate()`. Subclasses must inherit from `Appliance` and implement `operate()`; for example, a washing machine outputs “Washing clothes...,” while a refrigerator outputs “Storing food and beverages...”. In `Main`, create objects of different subclasses and call `turnOn()`, `displayBrand()`, `operate()`, and `turnOff()` to observe the differentiated behaviors under a unified interface. The expected output demonstrates the complete operational processes of an LG washing machine and a Panasonic refrigerator, illustrating the combination of abstract design and polymorphism.

**Week 8-9：Collection Framework and File Handling**

In this tutorial, create a file named `Main.java` in the `week_8-9` directory to build a simple desktop to-do list application. The scenario is as follows: The user wants to replace paper-based notes with a Java program that allows them to add tasks, view all tasks, save tasks to a file, and automatically load historical tasks at startup. The tutorial proceeds in two steps: First, create an `ArrayList` to allow users to enter three to-do items and display them in the terminal; second, enhance the program by using `BufferedWriter` to write all tasks to the `task.txt` file, then use `BufferedReader` to read the file’s contents and display them, thereby implementing persistent data storage and loading. This week’s tutorial comprehensively applies two major technical modules: the Java Collections Framework and the `java.io` file handling library.

**Week 10：GUI (Graphical User Interface) Programming**

In the tutorial, create Questions.java and QuizBattleGUI.java in the week_10 directory to build a graphical user interface (GUI) for a quiz battle application. The Questions class encapsulates the question text, two answer options, and the correct answer, and provides getter methods such as getQuestion() as well as the isCorrect() method for validation. QuizBattleGUI inherits from JFrame and implements the ActionListener interface. It contains two labels (lblQuestion and lblResult) and two buttons (btn1 and btn2). It uses setBounds() to set an absolute layout, initializes the window title, size, and components in the constructor, and registers event listeners for the buttons. This week’s tutorial also covers Git cloning (`git clone`) and opening files in VS Code (`code .`). Students are required to push their completed code back to GitHub, completing the full process from local development to remote collaboration.

## 5.Technologies Used

The course focuses on building a technology stack around the Java ecosystem, covering multiple aspects such as the core language, standard libraries, development tools, and version control.

In terms of programming languages, this course uses Java SE (Standard Edition) as its programming language. Java is an object-oriented, cross-platform, strongly typed programming language introduced by Sun Microsystems in 1995; its “write once, run anywhere” capability relies on the JVM (Java Virtual Machine). The core syntax elements used in the course include class and object definitions, constructors, the `this` and `super` keywords, access modifiers (`private`, `protected`, `public`), inheritance (`extends`), method overriding (`@Override`), abstract classes and abstract methods (`abstract`), and interfaces.

At the standard library level, the course focuses on three major modules. The first is the Java Collections Framework, which provides dynamic containers such as ArrayList, HashSet, and HashMap. Combined with generics, it enables type-safe object storage and manipulation, supports built-in methods such as add, remove, get, and size, and serves as a replacement for traditional fixed-length arrays. Second is the `java.io` package, used for file and input/output processing. Core classes include `File` (abstraction for files and directories), `FileReader`/`FileWriter` (text reading and writing), `BufferedReader`/`BufferedWriter` (efficient buffered reading and writing), and `FileInputStream`/`FileOutputStream` (byte streams), which enable data persistence through the stream model. Third is Swing and AWT, used to build graphical user interfaces (GUIs). Core components include `JFrame` (main window), `JLabel` (label), `JButton` (button), `JTextField` (text field), and `JPanel` (panel), which work in conjunction with the `ActionListener` interface and the `actionPerformed` method to implement event-driven programming.

In terms of development tools, the course uses GitHub Codespaces as the cloud-based development environment, combined with the VS Code editor for local development, and utilizes the Java compiler (javac) and runtime (java) to compile and execute programs. In terms of version control, the course uses Git throughout to manage versions and hosts code repositories on the GitHub platform. Core commands include `git init` (initialize), `git clone` (clone), `git status` (view status), `git add` (stage), `git commit` (commit), and `git push` (push), forming a complete distributed collaboration workflow.

**Step 2: Get the code**

Log in to your GitHub account, navigate to your personal OOP course repository, click the green “Code” button, switch to the HTTPS tab, and copy the repository URL. Open your local terminal (CMD or PowerShell), navigate to the directory where you want to store the project, and run the clone command: `git clone https://github.com/wangzehua89/WANG-ZEHUA_object-oriented-programming-tutorials.git`. Once cloning is complete, enter the project directory: `cd your-repository-name`. If you're using VS Code, you can run `code .` to open the editor in the current directory.


**Step 3: Compile and Run**

Java programs must be compiled before they can run. Navigate to the directory for the corresponding week (e.g., `cd week_8-9/`), and run the program using the `java` command: `java Main.java`. The program will then execute in the terminal and display the results.

**Operating Precautions**

First, make sure to run the command from the directory containing the .java source files; otherwise, use the full path. Second, file-processing programs (such as those in Weeks 8–9) generate data files (e.g., task.txt) in the same directory when run; these files will be automatically read upon subsequent runs, so do not delete them manually. Third, GUI programs rely on a graphical environment and cannot display windows properly on a command-line-only server without a graphical interface; they must be run in a local desktop environment or in Codespaces. Fourth, after making any code changes, you should execute `git add .`, `git commit -m “commit message”`, and `git push` in that order to push the updates to GitHub, ensuring that assignments are submitted on time. Fifth, if you encounter compilation errors, first check whether the class name matches the filename (Java requires that the name of a `public` class must exactly match the filename), whether the case is correct, and whether semicolons and parentheses are complete. These are the most common issues for beginners.

## 7.6 Understanding Object-Oriented Programming Concepts

If improving one’s technical skills represents the “technique” level, then deepening one’s understanding of object-oriented programming concepts represents the “philosophy” level. The greatest value of this ten-week course lies not in how many new APIs I learned, but in the fact that, for the first time, I gained a systematic understanding of the four pillars of object-oriented thinking and their intrinsic connections from the perspective of design philosophy.

Encapsulation is the concept I understand most thoroughly. In the past, although I wrote private fields and getters/setters, I mostly copied them as “boilerplate code” without truly understanding their value. The documentation.txt writing exercise in Week 5 forced me to answer the question, “Why use `private`?”—and I realized that the essence of encapsulation isn’t the act of “hiding” something, but rather “ensuring data remains in a valid state through a controlled interface.” Take a bank account as an example: if `balance` were public, external code could directly assign a negative value to it; however, by using `private` combined with a `deposit()` method, we can include a validation check like `if (amount > 0)` within the method, thereby mechanically preventing invalid states. This philosophy of “using the type system and access control to block errors at the boundary between compile time and runtime” is the cornerstone of software reliability.

Inheritance has given me a new understanding of the true meaning of “code reuse.” In the past, I thought inheritance was simply “borrowing code from a parent class”—a lazy way to reuse code. The course helped me realize that the true value of inheritance lies in establishing an “is-a” semantic relationship—Student is a Person—so Student can inherit the attributes and behaviors of Person and extend or specialize them based on that foundation. This semantic relationship cannot be established between just any two classes; misusing inheritance (such as having a “car” inherit from “wheel”) would undermine the clarity of the type system. The design of Person, Student, and Lecturer in the course serves as a prime example of the “is-a” relationship.

Polymorphism was the concept I found most confusing in the past, but one that now makes perfect sense to me. The tutorials from Weeks 3–4 helped me understand that the power of polymorphism lies in the fact that “the caller does not need to know the specific type; it relies solely on the abstract interface.” When writing `Person p = new Student(); p.introduce();` in the main method, the caller is only concerned with the fact that “p is a Person and has an introduce() method,” without caring whether p is actually a Student or a Lecturer. This design philosophy of “relying on the abstract, not the concrete” gives the system exceptional extensibility when facing changing requirements—adding a new subclass requires no changes to the caller’s code. This is precisely the foundational concept for learning design patterns later on (such as the Strategy Pattern and the Factory Pattern).

Abstraction is the counterpart to encapsulation. The `Appliance` abstract class from Week 7 helped me understand that the essence of abstraction is “defining a contract and deferring implementation.” The abstract class defines a common contract—that “all appliances have a brand, can be turned on, can be turned off, and can operate”—but leaves the “specifics of how they operate” to the subclasses. This mindset of “defining the interface first, then filling in the implementation” is the foundation of layered design in large-scale software systems—upper-level modules depend on abstract interfaces, lower-level modules provide concrete implementations, and layers are decoupled through abstraction. I had actually been using this approach in my work before (such as calling an interface without concerning myself with the implementation class), but I had never realized so clearly that it had a specific name: “abstraction.”

The intrinsic connections among the four pillars are also a key insight that has deepened my understanding. Encapsulation ensures “internal state security”; inheritance establishes a “type hierarchy”; polymorphism enables “different behaviors for the same interface”; and abstraction defines “contract specifications.” These four concepts are not isolated but build upon one another in a progressive manner: without encapsulation, data would be subject to arbitrary tampering, and methods inherited from other classes would lose their reliable foundation; without inheritance, polymorphism would lack a type foundation; without abstraction, inheritance would lack a starting point—namely, “what to inherit from.” Through ten weeks of progressive exercises, the course enabled me to weave these four concepts into a complete logical chain, rather than treating them as four isolated terms.
